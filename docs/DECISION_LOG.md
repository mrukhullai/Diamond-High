# Diamond High — Decision Log

This log records decisions that meaningfully affect the project's direction. It preserves historical decisions and records when later decisions supersede them; it is not intended to record every small implementation choice.

## D-001 — Diamond High is the project identity
**Status:** Accepted  
**Decision:** Use Diamond High as the name of the education product.  
**Reason:** It is the user's established project identity.

## D-002 — Build to learn
**Status:** Accepted  
**Decision:** The project must support real skill development, not merely produce code quickly.  
**Reason:** The creator wants to understand, explain, and eventually extend the implementation independently.

## D-003 — The first release is a prototype
**Status:** Accepted  
**Decision:** The first release is a focused working prototype rather than a production-ready platform.  
**Reason:** This keeps the work credible and manageable while allowing the concept to be demonstrated and reviewed.

## D-004 — Initial demonstration combines public identity and learning
**Status:** Superseded by D-011  
**Decision:** The original plan prioritised a public-facing school website and a small integrated learning demonstration.  
**Reason:** This was the initial project framing. The product identity has since been clarified as an e-school.

## D-005 — Header and hero come first
**Status:** Reframed by D-011 and Phase 0  
**Decision:** The original immediate UI milestone was a conventional school homepage header and hero.  
**Reason:** The landing page remains important, but its content and information architecture must now communicate an e-school and its learner journey.

## D-006 — Initial human-centred visual direction
**Status:** Superseded as a visual direction; human-centred principle retained  
**Decision:** The original documents proposed a warm, natural, expressive, blue/white school website.  
**Reason:** This records the historical direction. The current exploration is calmer, more minimal, and navy-led; the exact design system remains subject to review.

## D-007 — Mastery with support
**Status:** Accepted  
**Decision:** Learning should be taken seriously; difficulty should lead to support and reassessment rather than abandonment, while progression should not falsely imply mastery.  
**Reason:** This balances meaningful academic standards with a humane learning environment.

## D-008 — Defer unnecessary technical commitments
**Status:** Accepted  
**Decision:** Do not lock in a framework, backend, database, authentication model, or AI stack before requirements justify it.  
**Reason:** Early technical choices should serve the actual prototype and learning goals.

## D-009 — Feedback should shape later scope
**Status:** Accepted  
**Decision:** Treat assumptions about learners and institutions as hypotheses until tested with relevant feedback.  
**Reason:** The e-school may later support different learning contexts and institutional needs.

## D-010 — Avoid real sensitive learner data in the prototype
**Status:** Accepted  
**Decision:** Use sample or fictional data for the first demonstration.  
**Reason:** Real learner information is unnecessary for proving the initial concept and introduces avoidable privacy risks.

## D-011 — Diamond High is primarily an e-school
**Status:** Accepted  
**Decision:** Diamond High's current identity is an online learning platform, not a conventional school's public website. It should centre on course discovery, lessons, practice, feedback, demonstrated understanding, and learner progress. Integration with a real school may be considered later, but it is not the current product identity.  
**Reason:** This gives the product a clearer purpose and makes the learner experience central.

## D-012 — Scholar Build is the pedagogical reference
**Status:** Accepted  
**Decision:** Use Scholar Build as a reference for educational principles such as understanding before memorisation, reasoning, application, evidence-based mastery, disciplined practice, and continuous improvement. Do not copy its product structure or assume every feature is validated.  
**Reason:** It provides an existing conceptual foundation and avoids unnecessary duplicate research while preserving Diamond High's independent product identity.

## D-013 — Lunacy is the primary design workspace
**Status:** Accepted  
**Decision:** Use Lunacy for ongoing interface design. Existing Figma work, if recoverable, is reference material rather than the source of truth.  
**Reason:** The project is moving to a PC-first Lunacy workflow and will establish a fresh, organised design workspace.

## D-014 — Current visual exploration is navy-led and minimalist
**Status:** Working direction  
**Decision:** Explore a calm, minimal interface with deep navy foundations, lighter navy surfaces, restrained accents, and clear hierarchy.  
**Reason:** This reflects the user's current design preference. Exact tokens and components remain subject to design review.

## D-015 — Theory, independent practice, milestone review
**Status:** Accepted  
**Decision:** Teach relevant design/engineering theory, let the creator apply it independently, then inspect and review at meaningful milestones. Avoid unnecessary click-by-click instruction and constant screenshot requests.  
**Reason:** The project should develop independent design and engineering judgement, not just produce a result by following instructions.

---

When a decision changes, update its status and explain why. Add new entries for consequential changes rather than silently rewriting the project's history.
