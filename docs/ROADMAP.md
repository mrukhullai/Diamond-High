# Diamond High — Roadmap

This roadmap is directional, not a fixed schedule. Progress depends on learning, available time, and feedback. Stages can be revised when evidence warrants it.

## Stage 0 — Project foundation
- [x] Create the GitHub repository.
- [x] Add the project README.
- [ ] Establish the founding charter.
- [ ] Establish the product brief.
- [ ] Define the first prototype's scope.
- [ ] Record major decisions and the working approach.
- [ ] Review the foundation documents for consistency.

**Exit condition:** We agree on the purpose, audiences, principles, current scope, and next milestone.

## Stage 1 — Homepage header and hero
- Clarify the immediate purpose of the header and hero.
- Explore layout, content hierarchy, imagery, typography, and visual tone.
- Build the interface in small, understood steps.
- Check responsive behaviour and accessibility.
- Review and refine the result before expanding the page.

**Exit condition:** The header and hero communicate the intended identity and work well across common screen sizes.

## Stage 2 — Complete public homepage
- Extend the established visual system into the rest of the homepage.
- Add only the sections that support the initial school demonstration.
- Ensure navigation and links have meaningful destinations.
- Review consistency, responsive behaviour, and accessibility.

**Exit condition:** A coherent public-facing homepage can be demonstrated.

## Stage 3 — Small learning journey
- Select one representative learning topic or lesson.
- Build a clear lesson presentation.
- Add one meaningful learner activity.
- Give feedback and show a simple, honest progress state.
- Keep implementation and data handling appropriate for a prototype.

**Exit condition:** A reviewer can follow the learner journey and understand what the prototype demonstrates.

## Stage 4 — Review and school demonstration
- Gather feedback from relevant people where possible.
- Separate observed feedback from assumptions and personal preferences.
- Prioritise improvements by user value and effort.
- Prepare a clear explanation of current capabilities and limitations.

**Exit condition:** The next iteration is based on evidence rather than guesswork alone.

## Stage 5 — Engineering improvement
As justified by the product, improve testing, reusable components, accessibility, performance, maintainability, and deployment workflow. Choose specific technical tools only when the requirements make the trade-offs clear.

## Later possibilities — Not current commitments
- Learner accounts and saved progress.
- Educator tools and course management.
- More advanced progress charts and analytics.
- AI-supported learning.
- Independent learner experiences.
- Multi-school support.

## Working rhythm

For each milestone:
1. Agree on a small, observable goal.
2. Inspect the current project and relevant files.
3. Identify the skill or concept being practised.
4. Build in manageable increments.
5. Test the behaviour and review the result.
6. Record meaningful decisions and unresolved issues.
7. Move forward when the result is understood well enough to maintain.

Avoid inventing deadlines without considering the user's actual schedule and energy. Prefer steady, demonstrable progress over rushed volume.
